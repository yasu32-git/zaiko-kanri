# 在庫管理・買い物リスト PWA

夫婦2人で共有する日用品・食材の在庫管理＆買い物リストアプリ。
DBは夫のGoogle Drive上のスプレッドシート、APIはGoogle Apps Script (GAS)、フロントは静的PWA（GitHub Pages等でホスティング）。

## 構成

```
在庫管理/
├── README.md          ← このファイル（要件・設計・セットアップ手順）
├── gas/
│   └── main.gs        ← GASにコピーするAPIコード
└── docs/              ← PWA本体（GitHub Pagesの公開元フォルダ。/docs 以外は選べない場合が多いためこの名前）
    ├── index.html
    ├── style.css
    ├── app.js         ← UI・同期ロジック
    ├── db.js          ← IndexedDB ラッパー
    ├── sw.js          ← Service Worker（オフラインキャッシュ）
    ├── manifest.webmanifest
    └── icons/         ← ホーム画面アイコン
```

## 技術選定の理由

| 項目 | 選定 | 理由 |
|---|---|---|
| フロント | Vanilla JS (フレームワークなし) | 画面数が少なく、ビルド不要でGitHub Pagesに置くだけ。Node環境の維持コストゼロ |
| ホスティング | GitHub Pages（無料） | 静的ファイルのみで完結。Vercel/Cloudflare Pagesでも同じファイルがそのまま動く |
| DB | Googleスプレッドシート | 夫がMac/iPhoneから直接編集してマスタを常時カスタム可能 |
| API | GAS Webアプリ | 無料・認証不要のURL1本で完結。POSTは`text/plain`でCORSプリフライト回避 |
| オフライン | Service Worker + IndexedDB | 閲覧・更新ともオフライン可。更新はキューに積み、復帰時に自動同期 |
| 競合解決 | Last-Write-Wins | 各レコードの`更新日時`を比較し、新しい方を採用 |

## スプレッドシートのシート構成

スプレッドシートに以下の3シートを作成します（GASの `setupSheets()` を実行すると自動生成されます）。

### 1. `品目マスタ` — 現在の状態を持つマスタ

| 列 | 内容 | 例 |
|---|---|---|
| id | 一意ID（自動採番、編集しない） | `itm_1724300000000_ab3` |
| 品名 | | 牛乳 |
| カテゴリ | 自由入力 | 食材 |
| 購入先 | カンマ区切りで複数可 | コストコ,業務スーパー |
| 在庫数 | 数値 | 3 |
| 単位 | | パック |
| 緊急度 | `通常` / `急ぎ` / `必須` | 必須 |
| 買い物リスト | TRUE/FALSE | TRUE |
| 購入期日 | 急ぎでない物の期日（任意） | 2026-09-30 |
| メモ | 任意 | |
| 更新日時 | LWW用タイムスタンプ（ISO文字列、自動更新） | |
| 削除 | TRUEで論理削除 | |

夫がシートを直接編集する場合は「更新日時」を空にするか手を付けなくてOK（GAS側で読み取り時にそのまま返し、アプリからの更新はタイムスタンプ比較で行う。**シート直編集を確実に反映したい場合は「更新日時」列を消す**と、次回同期でシート側が必ず勝つ）。

### 2. `購入履歴` — 購入アクションの追記専用ログ（消費ペース算出の元データ）

| 列 | 内容 |
|---|---|
| 日時 | 購入日時（ISO） |
| 品目ID | |
| 品名 | 記録時点の品名（シート上で読みやすくするため） |
| 購入数 | |
| 購入先 | |
| 購入後在庫 | |

消費ペースはアプリ側で「直近の購入履歴の合計購入数 ÷ 経過日数」から1日あたり消費量を推定し、「残り◯日」を表示します。

### 3. `購入先マスタ`

| 列 | 内容 |
|---|---|
| 店名 | コストコ、業務スーパー、ダイソー など |
| 表示順 | フィルターチップの並び順（数値） |

## セットアップ手順

### Step 1: スプレッドシートとGASの準備

1. 夫のGoogleアカウントで新規スプレッドシートを作成（名前は任意。例「在庫管理DB」）。
2. メニュー「拡張機能 → Apps Script」を開く。
3. `gas/main.gs` の内容をエディタに全文貼り付けて保存。
4. エディタ上部の関数選択で `setupSheets` を選んで実行（初回は権限承認あり）→ 3シートとサンプル行が生成される。
5. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
6. 発行された **ウェブアプリURL**（`https://script.google.com/macros/s/.../exec`）を控える。

> URLを知っている人は誰でも読み書きできる状態になります。夫婦利用の実用上は「推測不能な長いURL」が事実上の鍵ですが、気になる場合は `main.gs` 冒頭の `API_KEY` に任意の合言葉を設定してください（アプリの設定画面にも同じ値を入れます）。

### Step 2: PWAのデプロイ（GitHub Pages の例）

1. GitHubに新規リポジトリを作成（Public）。
2. このリポジトリ（`docs/` にPWA本体が入った状態）をそのまま push。
3. リポジトリの Settings → Pages → Branch: `main` / `/docs` で公開。
4. 発行されたURL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）をiPhoneのSafariで開く。

### Step 3: 初期設定とホーム画面追加

1. アプリを開くと初回に設定画面が出るので、Step 1のウェブアプリURL（と API_KEY を設定した場合はその値）を入力して保存。
2. Safariの共有メニュー →「ホーム画面に追加」。妻のiPhoneでも同様に。

## GASコードを更新したとき

「デプロイ → デプロイを管理 → 編集(鉛筆) → バージョン: 新バージョン → デプロイ」。**新しいデプロイを作るとURLが変わってしまう**ので、必ず既存デプロイの更新で。

## ローカルで動作確認する

Macで見た目や動作を確認したいときは、`docs/` を静的サーバで配信します。

```bash
python3 -m http.server 8765 --directory docs
```

ブラウザで `http://localhost:8765` を開きます（`file://` で開くとService WorkerとES Modulesが動きません）。

アイコンを作り直したい場合:

```bash
python3 scripts/generate_icons.py
```

## 消費ペースの算出方法

`購入履歴` シートから、品目ごとに「最初の購入から最後の購入までの期間」と「最後の購入を除く購入数の合計」を取り、

```
1日あたりの消費量 = 最後を除く購入数の合計 ÷ 経過日数
残り日数 = 現在の在庫数 ÷ 1日あたりの消費量
```

として一覧に「残り約◯日」を表示します。購入が2回未満、または期間が1日未満の品目は表示しません（推定できないため）。

## 同期の仕組み（概要)

- 起動時: IndexedDBのキャッシュを即表示 → バックグラウンドでGASから全件取得 → 各品目の`更新日時`を比較して新しい方を採用（LWW）→ 再描画。
- 更新時: まずローカル(IndexedDB)に反映して即UIに反映 → 送信キューに積む → オンラインなら即送信。オフラインなら `online` イベントと次回起動時に自動送信。
- GAS側も受信した各レコードの`更新日時`とシート上の値を比較し、新しい場合のみ書き込む。購入履歴は追記専用なので競合しない。

Service Workerはネットワーク優先（取得できたらキャッシュを更新、失敗時のみキャッシュを返す）にしています。キャッシュ優先にするとアプリを更新しても古いJSが配信され続けるためです。オフライン時はキャッシュから起動します。

## 実装状況と次のステップ

### 完了

1. スプレッドシートのテーブル設計（マスタ／履歴ログ／購入先マスタの3シート分離）
2. GAS API（`doGet`で全件取得、`doPost`の`sync`で更新送信と取得を1往復、LWW判定、`LockService`による排他）
3. PWAフロント（在庫一覧・買い物リストの2タブ、購入先フィルター、1タップのリスト追加、ステッパーでの在庫増減、購入済み処理、品目の追加・編集・削除）
4. オフライン対応（Service Workerによる外殻キャッシュ、IndexedDBのデータキャッシュ、更新キュー、オンライン復帰時の自動送信）
5. 消費ペースの算出と表示
6. ブラウザ上でのモックAPIを使った同期テスト（キュー送信、LWWマージ、オフライン→復帰の再送、消費ペース表示を確認済み）

### 残っているステップ（ユーザー作業）

1. **スプレッドシート作成とGASデプロイ** — 上記「Step 1」の手順。ここだけは夫のGoogleアカウントでの操作が必要。完了済み。
2. **ホスティング** — `docs/` をGitHub Pagesに公開（上記「Step 2」）。完了済み: https://yasu32-git.github.io/zaiko-kanri/
3. **実機での確認** — iPhoneのSafariで開き、設定にウェブアプリURLを入れて同期を確認 → ホーム画面に追加。妻のiPhoneでも同様に。
4. **マスタの実データ投入** — 購入先マスタに実際に使う店舗名を入れ、品目を登録。シートに直接行を追加した場合は、スプレッドシートのメニュー「在庫管理 → 空のID/更新日時を埋める」を実行する。

### 実機確認後に検討したい改善

- 在庫一覧の並び順やカテゴリの表示順をシート側で制御できるようにする
- 買い物リストでの複数品目の一括購入済み
- 消費ペースからの購入提案（残り日数がしきい値を切ったら自動でリスト入り）
